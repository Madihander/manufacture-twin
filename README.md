# Saryarka Twin — цифровой двойник завода «СарыаркаАвтоПром»

Прототип для **Qostanai Industry Hackathon 2026**, кейс №2 АО «Группа компаний Аллюр» — «Цифровой двойник автомобильного завода».

Веб-приложение показывает сборочное производство в реальном (модельном) времени: 2.5D-карта цеха с движущимися кузовами, KPI участков, инциденты, аналитика для руководства, прогнозы ИИ и моделирование «что если».

**Открыть без установки: https://manufacture-twin.vercel.app**

## Запуск

```bash
npm install
npm run dev
```

Откройте http://localhost:5173 (рассчитано на экран 1920×1080, минимум 1440 px по ширине). Интернет не нужен: шрифты и 3D-модели лежат локально.

Сборка для публикации: `npm run build` → статические файлы в `dist/`.

### ИИ-ответы (DeepSeek / OpenRouter)

Чат «Спросить двойника» отправляет вопрос и снимок данных двойника в серверную функцию `api/ask.ts`, которая обращается к DeepSeek напрямую или через OpenRouter (провайдер определяется по ключу: `sk-or-…` — OpenRouter). Ключ хранится только на сервере:

- локально — в `.env.local` (скопируйте `.env.example`, вставьте ключ в `DEEPSEEK_API_KEY`); файл не попадает в git;
- на Vercel — в Settings → Environment Variables (`DEEPSEEK_API_KEY`, необязательно `DEEPSEEK_MODEL`).

Без ключа или без интернета чат отвечает офлайн-шаблонами по тем же данным — демонстрация не ломается.

## Что внутри

### Экран «Топология»
- Изометрическая 3D-сцена цеха: Склад комплектующих → Сварка → Окраска → Сборка → ОТК → Склад ГП. Роботы, окрасочная камера, печь, сканеры ОТК, краны, машины трёх моделей (Onix, Cobalt, JAC J7).
- Кузова двигаются по линии из симуляции, в буферах копятся очереди, в аварии корпус подсвечивается красным.
- Посты сборки работают: гайковёрты опускаются к кузову, подъёмники подают колёса, лампы-андоны горят по состоянию участка (зелёный — работа, жёлтый — простой, красный мигающий — авария). На ОТК светящаяся рамка сканера проходит вдоль каждого кузова. При остановке оборудование замирает.
- Клик по участку, оборудованию или кузову: камера подлетает, справа открываются KPI (план/факт, OEE = доступность × производительность × качество, брак, загрузка), телеметрия датчиков, журнал инцидентов, причины брака, история простоев.
- Слежение за кузовом: маршрут по участкам, время на участке против норматива, ожидаемый выпуск.
- Слои и тепловая карта (OEE / брак / риск), мини-карта, поиск по оборудованию.
- Нижняя панель: пуск/пауза, скорость 1–32×, таймлайн смены с отметками инцидентов (клик — перемотка к событию).

### ИИ-диспетчер
- Прогнозы **считаются кодом**, а не «придумываются» языковой моделью: тренд датчика за последний час → время до выхода за границу нормы → вероятность остановки. Плюс брак выше порога, узкие места по очередям и риск невыполнения месячного плана.
- У каждой карточки есть признаки, рекомендация, эффект в автомобилях и «Почему такой прогноз?».
- «Спросить двойника» — ответы по данным модели с кликабельными ссылками на объекты карты.
- Заявка на ТО создаётся из карточки прогноза: комментарий заполняется рекомендацией ИИ.

### Журнал заявок ТО
- Значок в шапке с числом открытых заявок. В журнале — заявка на каждый простой из журнала простоев (01–02.10 — данные кейса) и заявки, созданные из двойника.
- Статусы «Новая → В работе → Выполнена / Отменена», фильтры, поиск, переход к оборудованию на карте, выгрузка в Excel. Открытые заявки видны в карточке оборудования.
- Созданные заявки сохраняются в браузере; перед показом их можно убрать кнопкой «Очистить созданные».

### Экран «Сводка» — для руководства
- KPI периода, план/факт по линиям, OEE по участкам, брак против порога, Парето простоев, выпуск по моделям, прогноз выпуска до конца месяца с коридором.
- Журнал простоев с сортировкой, фильтры (период, участки, модель, смена, детализация).
- Экспорт с текущими фильтрами, формируется в браузере без сервера:
  - **PDF** — печатная компоновка A4: 3 страницы отчёта + журнал простоев;
  - **Excel (.xlsx)** — 8 листов (сводка, по сменам, динамика, брак, журнал простоев, Парето, прогноз месяца, риски ИИ) с числами, датами, формулами и автофильтром;
  - **Word (.docx)** — тот же отчёт, что PDF, с графиками, колонтитулами и нумерацией страниц.
- «Эффект для бизнеса»: сколько автомобилей и маржи даёт предотвращение части незапланированных простоев.

### Экран «Сценарии» — «что если»
Каждый запуск — новый прогон всей смены с другими параметрами: инцидент (оборудование, тип, длительность, время), такт, брак окраски, микс моделей, 3 смены, субботы. Результат сравнивается с базовой сменой: выпуск, прогноз месяца, OEE, простой, очереди, маржа. Сценарий можно проиграть на 3D-карте.

Типы остановок свои у каждого оборудования (у роботов — ошибка датчика, износ электродов, позиционирование; у конвейера — обрыв цепи, заклинивание подвески и т. д.), при выборе подставляется типичная длительность.

## Сюжет демонстрации

1. **21:42** — открываем «Топологию». ИИ предупреждает: ABB-01 — риск остановки ~73 % в течение 2 ч (вибрация растёт +55 % за 6 ч). Окраска в аварии: брак 4,2 % растёт вместе с засором фильтра Камеры-02.
2. Перематываем таймлайн на **19:45**: ИИ видит рост натяжения цепи и предупреждает «Конвейер-03 — риск остановки 86 % в течение 1 ч». В **20:15** цепь рвётся, сборка стоит 55 минут, очередь копится перед участком.
3. «Сценарии» → «ИИ предупредил: обрыва цепи нет»: **+15 автомобилей за смену, ≈ 6 млн ₸ маржи**.
4. «Сводка»: прогноз месяца **4 964 из 5 500** (недобор 536). Вывод: даже при 100 % плана мощность линии 22 рабочих дня × 2 смены × 120 = **5 280 < 5 500**, а план по моделям (Onix 2 500 + Cobalt 1 800 + J7 500 = **4 800**) не покрывает цель. «Сценарии» показывают, что 3 смены закрывают план.

## Данные и допущения

- Данные кейса (`src/data/seed.ts`) перенесены один в один. Строки «план 120 / факт» трактуются как **одна смена**: иначе мощность была бы 2 640 авто в месяц при цели 5 500.
- 01–02.10 (смена 1) — реальные данные кейса. Остальные дни октября смоделированы детерминированно (фиксированное зерно, одинаково при каждом запуске).
- Текущая смена (15.10, смена 2) — дискретная симуляция: такт 4 мин, места на участках, буферы, остановки из статистики простоев кейса. Телеметрия 24 датчиков — модельная.
- Пороги из кейса (OEE ≥ 85 %, брак ≤ 2 %, простой ≤ 60 мин/сут) меняются в настройках, статусы пересчитываются сразу.

## Архитектура

```
src/data      данные кейса, история месяца, справочник участков и оборудования
src/sim       симуляция смены, телеметрия, KPI, прогнозы ИИ, сценарии, сводка
src/store     состояние (zustand): время, выбор, настройки, заявки ТО и их журнал, сценарии
src/scene     3D-сцена (three.js / react-three-fiber)
src/components экраны и панели интерфейса (shadcn/ui + Tailwind)
design/       макеты из Claude Design
```

Путь к промышленной версии: модуль `sim` заменяется адаптером к MES/SCADA (тот же формат снимков состояния), прогнозы дополняются моделями на исторических данных, языковая модель подключается через серверный прокси для пересказа прогнозов и ответов на вопросы.

Стек: React 19, TypeScript, Vite, Tailwind CSS v4, shadcn/ui, zustand, three.js (@react-three/fiber, drei), Recharts, exceljs и docx (экспорт).

Проверки: `npx tsc -b`, `npm run sim:check` (калибровка симуляции и прогнозов), `npx tsx scripts/overlap-check.ts`, `npx tsx scripts/scenario-check.ts`.
